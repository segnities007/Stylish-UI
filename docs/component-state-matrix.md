# Component state matrix

This is the acceptance matrix for the public component catalog. A component is not considered
production-ready because its default preview renders; each relevant interaction and data state
must have an example, semantics contract, and regression evidence.

| Component family | Required states | Current Linux evidence | Remaining adoption evidence |
|---|---|---|---|
| Atoms / controls | default, hover, focus, pressed, disabled, selected, long text, RTL, 200% | JVM smoke, interaction policy, contrast tests | Full visual matrix and device Dynamic Type/TalkBack/VoiceOver |
| Inputs / feedback | empty, invalid, loading, error, success, IME, focus restoration | content-state host, strings, semantics smoke | IME and screen-reader device scenarios |
| DataTable | 10k rows, filter, sort, paging, selection, resize, pin/freeze, keyboard, empty/error | headless `StylishDataTableState` + pure reducer tests, pure pipeline tests, stable sort, bounded page, JVM semantics | UI scroll/frame/memory SLO, column virtualization, RTL golden, full pointer/keyboard scenario |
| Tree / Transfer | deep tree, expansion, multi-select, keyboard, Escape, focus restoration | stack-safe tree engine, controlled `StylishTreeState`/`StylishTreeAction`, controlled `StylishTransferState`/`StylishTransferAction`, pure reducer tests, controlled `StylishTransferSelectionMode`, Transfer checkbox semantics | 100k-node instrumentation, IME and device focus scenarios |
| Charts | finite/NaN/negative/zero/missing, ticks, selection, legend, RTL, large series | deterministic math tests, semantics, 500-point render bound, hoisted `StylishChartState`/`StylishChartAction` with controlled renderer | color-vision visual evidence, frame/memory/path benchmark |
| Menus / navigation | hover, keyboard arrows, Enter/Space, Escape, selection, long labels | split responsibility files, keyboard semantics | browser DOM workflow and device back/focus behavior |

The matrix is deliberately honest: “Linux evidence” is not a substitute for platform evidence.
The release checklist must link each row to a screenshot/semantics artifact and a platform run, or
keep the row blocked.

## Machine-generated public-surface audit

The source-level audit is generated by
[`scripts/verify-catalog-state-matrix.py`](../scripts/verify-catalog-state-matrix.py) and is
wired into the root `check` lifecycle as `checkCatalogStateMatrix`. It records all public
common `@Composable` declarations and all catalog `DemoComponent` entries in both directions:

- `mapped`: a visual public symbol is referenced by at least one copy-ready catalog demo;
- `missing`: a visual public symbol has no matching catalog demo and remains an adoption gap;
- `api-doc`: a composable factory or foundation/theme helper is intentionally searchable in
  API/Dokka documentation rather than represented as a visual card.

The generated JSON and Markdown artifacts are written to
`build/reports/catalog-state-matrix/`. The policy source is
[`docs/catalog-state-policy.json`](catalog-state-policy.json), which fixes the state vocabulary
and family-specific required states. Evidence is source-level (for example, an `isLoading` or
`LayoutDirection.Rtl` token); it does not claim that a token has passed a rendered visual,
TalkBack, VoiceOver, browser screen-reader, or physical-device test. Those platform gates remain
separate and must be added before an adoption decision.
